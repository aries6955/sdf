# 锁定判据以计量线为单位,不是租户加日期

"这一期已收款,不许改读数"的判据是 **(计量线, 账期)**。

修复前判据是 **(租户, 日期)**:`span_hit()` 抹掉了账期所属的计量线 ——
`paid_spans()` 明明算出了 `line_id`,却没人用它比对。

## 为什么

一个租户同一路水电可以有两条计量线(两间房各一块水表,ADR-0012),
水电两路更是天然各一条。它们在同一天各划出一个账期是常态。

于是实测到这个缺陷:甲的水表与电表都在 2025-02-01 抄表,只收了**水费**那 100 元。
此时给电表补录 2025-01-15 的读数被拒,提示说「2025-01-01 ~ 2025-02-01 这一期已收款」——
而那一期电费一分钱没收到。

坏处不止"不能补录":用户按提示去删掉水费收款,会把本来正确的数据弄坏。
提示指向了一个不存在的事实,这是比拒绝更严重的问题。

## 决定

- `paid_spans()` 与 `paid_periods()` 的每一项都带 `line_id`。
- `span_hit(spans, line_id, reading_date, inserting)` 只比同一条计量线。
- `touched_by_reading(conn, line_id, ...)` 以线号为参数;它自己查该线的租户,
  因为冲抵本身是按租户算的(ADR-0017),两者不能混为一谈。

## 约束

- 冲抵仍按租户先欠先冲(ADR-0011/0017):钱记在人名下,不指定账单。
- 锁定的**范围**因此不等于冲抵的范围:冲抵跨线,锁定只在同一条线内。
  一条线的账期被收款波及时,先欠先冲可能先把钱落到该租户**更早**的另一条线上,
  那时这一期确实还没收到钱,不该锁。
